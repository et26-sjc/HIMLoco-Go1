# 观测、推理、执行链路与部署补丁

## 对照来源

- 官方 HIMLoco 接口基准：`InternRobotics/HIMLoco`，提交 `ef289acaa62795009363b7b819c9186690630441`。
- 用户指定 Go1 训练默认配置来源：`et26-sjc/HIMLoco-Go1`，提交 `c59f76349c4718da19aa9b055a830ac1a383f038`。
- 当前实际模型：根目录 `models/policy.pt`，SHA 见 README 和 `himloco.json`。
- 冻结实机版本：`20261025_forward_trial_3`。本次导出没有修改其 75 个 manifest 文件。

## 数据流

```text
Go1 MCU / SDK3.8 LowState
  → C++ lcm_position_him（2 ms）：关节、wxyz、原生 gyro、遥控器
  → LCM：相同 SDK tick 与时间标记的 IMU/关节状态
  → Python StateReceiver：配对、推进和新鲜度检查
  → JointMap / 坐标变换：SDK → 策略顺序、机身重力和角速度
  → 45 维观测 → 6 帧历史 [1,270]，最新帧在前
  → 单个 TorchScript：estimator + actor → [1,12]
  → 训练接口动作裁剪 ±100，接管期动作渐入
  → q_des = q0 + 0.25 * applied_action
  → 按名称映射到 SDK 顺序，LCM 下发 q_des、Kp=40、Kd=1
  → C++ 校验、SDK PositionLimit / PowerProtect(9)
  → LowCmd：mode 0x0A、dq=0、tau_ff=0 → SDK/MCU 伺服
```

±100 是训练动作接口裁剪值，不代表关节机械范围。目标超出 URDF 或 SDK PositionLimit 改写目标时会停止。本版没有额外动作平滑器或单步角度裁剪器；动作渐入仅发生在接管的 1 s。

## 单帧 45 维观测

| 索引 | 数据 | 缩放 |
| --- | --- | --- |
| 0:3 | `vx, vy, yaw_rate` 命令 | `[2,2,0.25]` |
| 3:6 | 原生 IMU gyro，转到机身坐标 | 0.25 |
| 6:9 | 机身坐标重力单位向量 | `R_WB.T @ [0,0,-1]` |
| 9:21 | 策略顺序关节位置 `q-q0` | 1 |
| 21:33 | 策略顺序关节速度 | 0.05 |
| 33:45 | 上周期实际应用的无量纲动作 | 不乘动作角度比例 0.25 |

观测裁剪 ±100，float32。每个控制周期只推进历史一次；状态 getter 不推进历史。JIT 在 CPU、单线程推理，加载后完成离线预热。外部不再调用 WTW 的 adaptation/body 网络。不会在真机重新加仿真噪声或随机延迟。

正常运行时 previous_action 是裁剪后的策略动作；接管渐入时是实际应用的 `alpha * action`。这是部署过渡，不能将该阶段等同于训练环境的 episode reset。

## 关节与坐标

| 腿 | q0 hip | q0 thigh | q0 calf |
| --- | ---: | ---: | ---: |
| FL 左前 | 0.1 | 0.8 | -1.5 |
| FR 右前 | -0.1 | 0.8 | -1.5 |
| RL 左后 | 0.1 | 1.0 | -1.5 |
| RR 右后 | -0.1 | 1.0 | -1.5 |

策略顺序 FL、FR、RL、RR；SDK 顺序 FR、FL、RR、RL。读反馈与写动作均按名称构造双向映射。不得因某条腿承重偏差直接交换关节索引。

采用 SDK 的 wxyz 姿态；x 前、y 左、z 上；使用原生 gyro 而非 Euler 差分。传感器到机身旋转 `R_BS=I`，基于被动三轴运动及关节人工粗核保留。没有将支架姿态当成精密水平参考，也没有自动减去某次静止倾角。实际训练运行的 DOF 导出文件缺失，顺序依据用户接受的固定默认配置及显式 sim2sim 配置；该假设写在根 JSON 中。

## 对官方/WTW 框架增加的部署逻辑

以下属于实机工程补丁，不是 HIM 神经网络算法的一部分：

1. **新 HIM 专用入口。** `scripts/deploy_policy.py` 载入 JSON 和单一 JIT；`--check` 默认离线，不开启 LCM。旧 `envs/lcm_agent.py`、`utils/deployment_runner.py` 不被当前入口调用。
2. **来源检查。** 权重 SHA、配置、按名关节映射与对齐记录门控；桥接编译摘要及 checksum 凭据检查。manifest 是完整性清单，不是数字签名或运动质量认证。
3. **状态配对。** 以 SDK tick 和桥接时间标记配对 IMU/关节，重复数据不延长有效期；时间判断使用单调时钟。
4. **标定与接管状态机。** WAIT_R2 → CALIBRATE → SETTLE → READY → RAMP → RUNNING。标定 3 s、增益 0.5 s 渐入、0.20 rad 标定容差、连续六帧真实历史、1 s 动作渐入。趴卧初始实测值允许有限超出训练 URDF，目标仍必须合法。
5. **独立桥接停止门控。** 首条有效命令前不执行旧 WTW 名义姿态；协议号 20261023，故障负号广播；命令 100 ms、状态 50 ms watchdog，L2、SDK 位置/功率检查，停止锁存。已修复时钟在锁外读取可能导致误超时的问题。
6. **控制诊断。** 同步记录状态、命令、目标、动作、推理与周期分段耗时、MCU 估计力矩。每帧保留 45 维观测，270 维完整历史在故障快照中保存，减少重复日志开销。
7. **遥控命令。** 当前上限为 `[0.30,0.10,0.15]`，轴符号 `[1,1,-1]`，死区 0.05。标定/渐入阶段速度命令保持零，RUNNING 后读取摇杆；不做 heading 或位置闭环。
8. **额外目标步长门控可关闭。** 原部署附加的 `max_joint_target_step_rad` 允许 null；本版按此前要求关闭此项，仅记录目标变化量。其他机械、跟踪、倾角、数据/周期新鲜度和按钮停止保留。

本次导出只增加可定位到自身目录的双终端启动、桥接准备与离线检查脚本；没有改变上述控制链路。具体阶段性修复保存在 `docs/history/`，当前参数以根 JSON 为准。
