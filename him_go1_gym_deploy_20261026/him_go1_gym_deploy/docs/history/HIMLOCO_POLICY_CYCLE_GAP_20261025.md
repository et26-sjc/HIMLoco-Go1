退出原因为 `Policy cycle gap 0.0696s`：Python 检查到相邻两次控制步骤开始时刻相差约 69.6 ms，超过 20 ms 周期 + 40 ms 允许迟到量。C++ 随后记录 `stop command`，上条命令年龄约 63.4 ms。这是 Python 主动停止后的锁存，尚未达到桥接 100 ms 命令超时门槛。

旧日志在控制计算结束后同步编码并写入所有数据，每帧还重复写入完整的 270 维历史。计时在写入前结束，因此单凭此次记录无法区分后续 JSON/文件 I/O、睡眠唤醒、线程调度或其他运行时停顿。不能把根因直接断言为推理耗时或网线延迟。

## 本次处理

1. 每个周期继续记录 45 维观测、关节、目标、原始/应用动作和历史计数，省去重复的 270 维历史 JSON；故障快照保留最后已发布周期的完整历史。控制器仍按原逻辑构造并使用完整历史，日志格式版本记为 2。
2. 增加纯策略调用、状态快照、控制计算、停止重查、发布、JSON 编码/写入、控制台/刷新以及实际睡眠时间。每帧记录上一完整周期的分段时间；故障记录同时带当前阶段和上一周期分段时间。
3. Python 捕获错误或 Ctrl+C 后先请求桥接停止，再整理错误日志；原有 finally 中的停止兜底保留。
4. 20 ms 周期、60 ms Python 间隔门槛、50 ms 状态新鲜度、100 ms 桥接命令看门狗、全部动作/姿态/跟踪门槛保留。标定容差继续为 0.20 rad；模型和推理合同不改。

发布包：`/home/unitree/himloco_releases/20261025_supported_trial_2`。C++ 没有改动，沿用已修复计时竞争的二进制及凭据。A、B 启动命令保持不变，需先 Ctrl+C 退出旧 A，再重新启动两个终端程序。
