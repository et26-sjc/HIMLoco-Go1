# 部署状态与已知问题

结论日期：2026-10-26。证据来自 2026-10-25 的检查、用户实物操作说明与最后一份已取得的行走日志。本次导出未连接成功 Go1，未新增实机试验。

## 可以基本确认的范围

- 固定 HIM 接口的数值链路已审查，观测 45×6、历史顺序、单 JIT、动作角度缩放和双向关节映射有离线核对。
- 本机 Go1 的十二关节身份/方向、IMU wxyz、gyro 与机身轴向已进行被动动作人工粗核；误操作和严格自动判定未通过项如实留档。
- 原机 `jetson-model-deployment` 镜像已成功加载本权重并完成 forward；随后实机在该环境下执行策略。
- 用户已观察到承重及前后行走。保留的最后一份日志有 3508 帧 RUNNING、约 70.14 s 正式运行，命令包含 ±0.30 m/s。
- 当前下发的名义增益为 Kp=40、Kd=1。RUNNING 增益系数均为 1；静止 MCU 力矩估计与 40/1 的 PD 计算更相符，不能据此当作固件增益回读。
- R2/L2 请求停止、锁存及相关异常分支已有实机触发记录。mode 0、零增益请求不是电气断电确认。

因此可把该版本作为“已实现基本实机闭环和前后行走的部署基线”。不能据此证明代码所有分支无误，或将任何后续问题直接归因于训练。

## 尚未解决

### 1. 低姿态、膝部触地、承重跟踪差异

用户多次报告能行走但机身很低、膝部触地，并说明仿真也存在低净空。保留日志中，前进时左前小腿目标角中位数约 -1.826 rad、实测约 -2.064 rad；右后约 -1.974/-2.204 rad。二者的平均实测减目标偏差分别约 -0.196/-0.185 rad，包含动态相位滞后和承重影响，不能把单周期差值全部当成静态误差。

结论：策略已主动要求屈腿，实机跟踪偏差进一步加深屈腿。关节数据不能直接测得膝离地高度；报告中的正运动学也只是相对机身/同腿足端的位置，不能替代接触力和地面参考。

固定训练参考中的 `collision=-0.0`，虽列出 thigh/calf/base 作为惩罚对象，其碰撞奖励实际权重为零；`base_height_target=0.30` 是软奖励目标；`init_state.pos[2]=0.42` 是 reset 高度，不是行走目标。`clearance_height_target=-0.20` 是脚相对机身的目标 z，不是离地 20 cm，现有足端奖励也不直接保证膝部净空。

下一步应在同一权重的仿真回放中记录机身高度、膝部最低点和非足端接触力，结合实机目标/实测跟踪定位。再决定训练奖励/模型修正或控制跟踪检查。当前没有给部署动作叠加“站高偏置”，也没有提高 Kp/Kd 来掩盖问题。

### 2. 模型来源和物理标定边界

实际训练 run 的完整配置快照、DOF dump 与训练记录尚未取得。按用户明确接受的默认 fork 配置作为依据，不能宣称已复核该权重的所有训练超参数。IMU 只做了轴向粗核，未用水平仪完成安装零点标定；关节编码器零位未重新校准。

### 3. 环境及停止边界

训练仿真 PD 力矩裁剪与真机固件电流/力矩上限不一定相同。MCU tau_est 是估计反馈，不是独立力矩传感器校准结果。LCM/SDK tick 新鲜度不能完整证明 UDP 端到端延迟；无线遥控器断链时 SDK 的行为未单独完成验证。

原镜像和 ARM64 桥接在这台 Go1 上有使用证据，但本次无法从机器人导出二进制或镜像。前台 SSH 掉线后的控制进程生命周期、无人值守后台运行、物理断电急停和自动重启不属于本导出已验证范围。

## 当前保留的阈值

| 项目 | 值 |
| --- | --- |
| 状态新鲜度 | 0.05 s |
| 命令 watchdog | 0.10 s，C++ 固定 |

| 机身倾角 | 0.50 rad |
| 关节跟踪误差 | 0.50 rad，比较当前状态与上一目标 |
| 标定容差 | 0.20 rad，连续 6 帧 |
| 周期允许迟到 | 0.04 s，结合 0.02 s 策略周期进行门控 |
| 单步目标增量停止 | null，关闭此附加项，仍记录变化量 |
| 机械目标 | 训练 URDF 检查 + SDK PositionLimit；不静默裁剪继续执行 |
| 功率保护 | SDK PowerProtect factor=9 |

这些是当前实机实验参数，不是厂家认证的安全范围。更换权重、机器人、SDK 或安装坐标后应建立新的对照记录。
